第 01 章 / QUICKSTART

三条命令,完成全套装配

从零开始到「官方技能全就位 + 项目记忆初始化」,总共只需要几分钟。每个代码块右上角都可以一键复制。

STEP 01 — 安装 Claude Code
terminal
$ npm install -g @anthropic-ai/claude-code
$ cd 你的项目 && claude

已安装可跳过。首次运行会引导登录;详细系统要求见文末官方文档链接。

STEP 02 — 接入官方技能市场
claude · 会话内执行
> /plugin marketplace add anthropics/skills
> /plugin install document-skills@anthropic-agent-skills
> /plugin install example-skills@anthropic-agent-skills

一次装齐第 02 章的 17 个官方 Skills。之后在对话里点名即可使用,例如「用 pdf skill 提取这份表单的字段」。

STEP 03 — 初始化记忆
claude · 会话内执行
> /init   # 自动生成项目 CLAUDE.md 草稿
> /memory # 随时查看 / 编辑各层记忆

生成草稿后,用第 04 章的模板对照修剪:删掉 Claude 自己能推断的内容,只留高信号规则。全局文件手动放到 ~/.claude/CLAUDE.md。

# 全局工作准则(适用于本机所有项目)

## 沟通
- 用中文与我交流;代码、命令、报错信息保持英文原样
- 先给结论再给理由;不确定就直说,不要编造 API 或配置项

## 行为边界
- 删除文件、git push --force、数据库迁移、改 CI 配置等
  破坏性/高影响操作:先说明影响范围,征得我确认再执行
- 永远不要把密钥、token、密码写进代码或提交历史;
  发现 .env / 凭据有泄露风险时主动提醒我
- 不要擅自升级依赖的大版本

## 工程纪律
- 改动最小化:只做被要求的事,不顺手重构、不加多余抽象
- 修完 bug 先运行相关测试再收工
- commit message 用 Conventional Commits(feat/fix/chore/docs…)
- 同一任务连续失败两次时,停下来复述你对问题的理解再继续

## 我的环境
- 时区 Asia/Shanghai;macOS + zsh;Node ≥ 20;包管理器默认 pnpm

# MyApp — 项目上下文

> 电商后台管理系统 · Next.js 15 + TypeScript + Prisma + PostgreSQL
> 详细架构见 @docs/architecture.md,不在此复述

## 常用命令(照抄执行,不要自行猜测)
- 开发:   pnpm dev
- 全部测试: pnpm test
- 单个测试: pnpm test -- --grep "关键词"
- 质量门:  pnpm lint && pnpm typecheck
- 迁移:   pnpm db:migrate(仅本地库;线上迁移走 CI)

## 目录速览
- app/        路由与页面(App Router)
- app/api/    API 路由,鉴权中间件在 app/api/_lib/
- lib/        领域逻辑与数据访问封装
- prisma/     schema 与迁移
- tests/      e2e;单测与源码同目录 *.test.ts

## 代码约定
- TypeScript strict,禁止 any;组件一律具名导出
- 数据访问只走 lib/db.ts 封装,不要直接 new PrismaClient
- 样式仅用 Tailwind,不写内联 style、不引入新 UI 库
- 新功能必须带 Vitest 用例,放在被测文件同目录

## 雷区(违反会出事故)
- prisma/migrations/ 里已存在的迁移文件一律只读
- app/api/webhooks/* 的签名校验逻辑不许改动
- CI 运行在 Node 20,不要使用更高版本才有的 API

## 工作流
- 涉及 >3 个文件的改动:先给出计划,确认后再动手
- 收工前必须通过:pnpm lint && pnpm typecheck && pnpm test

第 05 章 / WRITING RULES

CLAUDE.md 编写守则

它每个会话都会整段注入上下文——每一行都在和真正重要的规则抢注意力。官方与社区共识高度一致:短、准、只写 Claude 猜不到的。

DO / 值得写

  • 控制篇幅:社区普遍建议全文 200 行以内,精华版 80–120 行超长文件不会被逐字执行,只会被平均稀释
  • 命令写全、写死:构建 / 测试 / lint / 迁移,连 flag 一起给这是单条价值最高的信息,能省掉 Claude 三轮瞎猜
  • 只写「读代码猜不出、猜错代价高」的事实与禁区例:CI 的 Node 版本、不许动的迁移文件、签名校验逻辑
  • 用 @ 引用替代复述:@README.md、@docs/architecture.md支持相对/绝对路径,递归导入最深 5 层
  • 分层放置:行为进全局,事实进项目,局部规则进子目录懒加载让无关规则根本不进上下文
  • 硬约束交给 Hooks(如「每次提交前必须跑 lint」)Hook 在生命周期节点强制执行,不看 Claude 心情
  • 定期跑 /memory 复查各层内容并修剪、消除互相矛盾的规则两处规则冲突时,Claude 可能任选其一

DON'T / 别写

  • 人格设定:「你是一位资深工程师,请一步步思考」不改变具体行为的话 = 纯粹浪费指令预算
  • Claude 一个会话就能自学的东西(文件命名规律、依赖清单)自动记忆(MEMORY.md)会替它记住,写了就是重复
  • 多步骤操作流程该做成 Skill 按需加载,而不是每个会话硬扛
  • 整段架构文档复制粘贴一行 @ 引用即可,需要时 Claude 自己会去读
  • 真实密钥、token、密码——包括 CLAUDE.local.md 里写「去哪取」,不写值;这些文件不是保险箱
  • 把 CLAUDE.md 当成强制开关它是上下文不是防线;要「无论如何都拦住」,用 PreToolUse hook
第 06 章 / SKILL ANATOMY

开发者说明书:Skill 剖析、存放与排障

一个 Skill = 一个文件夹,而不只是一个 Markdown。三级渐进披露让它几乎零成本常驻:启动只读约 100 token 的元数据,任务匹配才加载正文,脚本与资料按需再读。

my-skill/SKILL.md — 逐字段注解
---
name: pr-review                # 必填,也是 /pr-review 命令名
description: >                 # 必填,决定「何时触发」的唯一线索:
  按团队标准审查 PR:安全、性能、  #   写清做什么 + 何时用 +
  测试覆盖。当用户提到"审查/review/ #   用户可能怎么说(触发词)
  看看这个 PR"时使用。
allowed-tools: Read, Grep, Glob  # 可选:限制可用工具(只读审查)
context: fork                  # 可选:在分叉上下文运行,不占主对话
agent: Explore                 # 可选:交给内置/自定义子代理执行
user-invocable: false          # 可选:仅 Claude 自动调用,不出现在斜杠菜单
---

# 审查流程
1. 用 Grep 定位改动涉及的模块与调用方
2. 对照 references/checklist.md 逐项检查
3. 输出:阻断项 / 建议项 / 可忽略项 三档报告

# Gotchas(最有价值的一节:真实踩过的坑)

高频排障

Skill 不触发?
九成是 description 写得太抽象。补上三要素:做什么(列具体功能)、何时用、用户可能说的触发词(中英文口语都覆盖,如「审查 / review / 看看这个 PR」)。改完直接提一次相关请求验证。
CLAUDE.md 规则被无视?
先跑 /memory:规则可能写在尚未懒加载的子目录文件里;再检查是否有两处规则互相矛盾(Claude 可能任选其一);仍不稳的硬约束,改写成 PreToolUse hook 强制执行。
会话越长越笨?
上下文接近装满时性能会下降。无关任务之间用 /clear 切断;长任务在填充率约七成时主动 /compact 聚焦要点;需要跨会话保留的结论,落盘到 CLAUDE.md 或让自动记忆(MEMORY.md)接手,别指望聊天记录。
装太多 Skills 有代价吗?
常驻成本极低(每个约 100 token 元数据),但描述相互重叠会让匹配变糊。同类只留最好的一个,让每个 Skill 只做一件事。
Skill、CLAUDE.md、Hook、MCP 怎么分工?
硬性事实与规矩 → CLAUDE.md;多步骤的「怎么做」→ Skill(按需加载);必须强制执行的动作 → Hook;连接外部数据与系统 → MCP,再用 Skill 教 Claude 怎么用好这些工具。
SECURITY / 安装第三方 Skill 前先通读它的 SKILL.md 与 scripts/——技能会影响 Claude 的行为并可能执行代码。优先官方与知名来源;来源存疑时,用 NVIDIA 开源的 Agent Skill 安全扫描器等工具审计 prompt injection、数据外泄与工具投毒风险。
