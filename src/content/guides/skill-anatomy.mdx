一个 Skill = 一个文件夹,而不只是一个 Markdown。三级渐进披露让它几乎零成本常驻:启动只读约 100 token 的元数据,任务匹配才加载正文,脚本与资料按需再读。

## SKILL.md 逐字段注解

export const skillTpl = "---\nname: pr-review                # 必填,也是 /pr-review 命令名\ndescription: >                 # 必填,决定「何时触发」的唯一线索:\n  按团队标准审查 PR:安全、性能、  #   写清做什么 + 何时用 +\n  测试覆盖。当用户提到\"审查/review/ #   用户可能怎么说(触发词)\n  看看这个 PR\"时使用。\nallowed-tools: Read, Grep, Glob  # 可选:限制可用工具(只读审查)\ncontext: fork                  # 可选:在分叉上下文运行,不占主对话\nagent: Explore                 # 可选:交给内置/自定义子代理执行\nuser-invocable: false          # 可选:仅 Claude 自动调用,不出现在斜杠菜单\n---\n\n# 审查流程\n1. 用 Grep 定位改动涉及的模块与调用方\n2. 对照 references/checklist.md 逐项检查\n3. 输出:阻断项 / 建议项 / 可忽略项 三档报告\n\n# Gotchas(最有价值的一节:真实踩过的坑)\n- webhooks 目录的签名校验改动一律标记为阻断项";

<Term title="my-skill/SKILL.md — 逐字段注解" copyTarget="#tpl-skill" codeId="tpl-skill" content={skillTpl} />

<p class="fig-note">文件夹里还可以放 <span class="mono">references/</span>(参考资料)、<span class="mono">scripts/</span>(可执行脚本)、<span class="mono">assets/</span>(模板产物)——在正文里告诉 Claude 它们的存在,它会在合适时机自己去读。自定义斜杠命令已并入 Skills:<span class="mono">.claude/skills/deploy/SKILL.md</span> 自动获得 <span class="mono">/deploy</span> 命令。</p>
